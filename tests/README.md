## 现有验收输入

[fixtures/schedule-cases.json](fixtures/schedule-cases.json) 含 12 个小型有效计划的人工期望值和 6 个非法依赖编辑输入：

- 计划覆盖原 proposal 的 2/3/4/2 例子、C 改为 6 天、从原计划移除 C → D、并列关键路径、独立任务、链、合并、单任务、空项目、无合并分支、多起点及不连通链。
- 每个有效例子提供任务、正数工期、前置任务，以及计划工期、关键任务集合和 ES/EF/LS/LF/总时差。空项目没有任务。
- 无前置任务从 Day 0 开始；独立任务可并行；结束时刻以相对自然日偏移量表示。所有终点的最晚结束按项目计算结束回推。
- 非法编辑覆盖自引用、重复关系、跨项目关系、直接环、间接环及不存在任务；都要求清晰拒绝且原有效计划不变。
- 夹具是预先记录的验收输入与期望，尚未连接测试运行器。关键任务列表表示集合，不应依赖数组顺序；有效拓扑顺序可以有多个。

工期使用整数只是这些例子的选择；不意味着已决定产品仅支持整数。日期映射、小数精度和数值比较策略应在 Week 1 明确。空计划 0 天是计算夹具基准，进度界面仍应展示“No tasks yet”，不要为完成比例除零。

## 执行记录要求

每次正式验收记录 AC 编号、代码版本、输入、期望、实际结果、通过/失败、执行者、日期和证据。拒绝依赖编辑需同时检查错误解释与持久化计划没有变化。性能记录须包含任务/依赖数、测试机器、编辑场景和耗时，不用未经测量的“流畅”代替结果。

失败用例保持可追溯，修正后只补充复测结果，不擦去原失败。Week 7 计划做集成测试和用户评估；Week 8 复测缺陷并整理测试、评估及贡献证据。避免将目标写成已经达成的成果。
